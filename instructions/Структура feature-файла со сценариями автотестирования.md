Feature-файл имеет определённую структуру и содержит служебные слова, задающие значения переменным, необходимым для
правильной работы фреймворка:
<table>
<tr><td>Функционал:</td><td>содержит два значения - Название набора и Название функционала, взятых в квадратные скобки. Для правильной сортировки результатов в Allure-отчетах названию предшествует порядковый номер.</td></tr>
<tr><td>Сценарий:</td><td>содержит название сценария. Должно быть уникальным в контексте указанного функционала. Также содержит порядковый номер в начале.</td></tr>
</table>
Каждый шаг начинается с новой строки с символа * (правильнее было бы указывать аннотацию Gherkin, но в текущей реализации фреймворка в этом мало смысла).

Перед указанием функционала и сценария с помощью символа @ задаются теги, позволяющие управлять составом запускаемых сценариев.
Теги, указанные перед словом Функционал относятся ко всем сценариям, описанным в этом feature-файле.
Теги, указанные перед словом Сценарий относятся только к данному сценарию.
Один и тот же тег может ссылаться на разные сценарии, в том числе и в разных файлах.

Теги можно перечислять в одной строке через пробел или в разных строках.
Для запуска сценариев из IntelliJ Idea необходимо указать теги через запятую в качестве значения опции scenario.tags в файле
runtime.properties.

Сценарий может быть описан как примитивными шагами, имеющими реализацию непосредственно в одном из Java-методов, так и с
помощью шагов, вызывающих другой сценарий, описанный в том же виде.

[Пример файла со сценарием автотеста](instructions/Пример файла со сценарием автотеста.feature)

Сценарии, вызываемые из основных сценариев, называются фрагментами или подсценариями и представлены в виде
feature-файлов в папке scenarioFragments.

[Пример файла с фрагментами сценариев](instructions/Пример файла с фрагментами сценариев.feature)

Любой фрагмент также может быть вызван из другого фрагмента или даже из самого себя (при условии, что реализация шагов
не допускает бесконечного зацикливания).

Фрагменты можно вызывать с параметрами, переданными в виде таблицы данных (см. пример, вызов подсценария "Найти клиента")
Также, в вызываемых фрагментах по умолчанию доступны тестовые параметры, значения которых были заданы в основном
сценарии.

Любой шаг сценария связан с java-методом, определяющим его реализацию. Перейти к этому методу можно по CTRL + click.
Плагин Cucumber for Java находит метод, соответствующий конкретному шагу с помощью регулярного выражения, заданного в
аннотации Gherkin (@И, @Когда, @Тогда, @То и других).
В текущей реализации фреймворка было решено не использовать другие аннотации, кроме @И, для упрощения работы со
сценариями.

Важно учесть, что каждый шаг должен соответствовать только одному методу с аннотацией @И, независимо от класса.
Такой метод является лишь "описанием" шага и не должен содержать реализации действий с объектами тестирования и сложной
логики.
Обычно метод, описывающий шаг, создаёт экземпляр класса, содержащего поля и методы тестируемого объекта и вызывает
соответствующий метод этого класса.

В начале сценария в большинстве случаев бывает удобно выполнить шаг, определяющий значения переменных, которые в
дальнейших шагах будут использоваться для заполнения полей, проверки их значений и т.п.
Для удобного хранения и представления тестовых данных используются файлы в формате yaml.
Чтобы шаг <u><i>* определить значения тестовых параметров</i></u> смог найти нужный файл, он должен располагаться в той
же папке, что и feature-файл и иметь такое же название.
Кроме того, yaml-файл должен содержать элемент списка с полем Сценарий, имеющим в качестве значения название сценария,
тестовые данные которого он описывает.

Для взаимодействия с элементами веб-страниц, фреймворк должен располагать информацией об этих элементах.
Для описания страниц используются yaml-файлы, которые расположены в папке resources/pages.
Файл страницы должен содержать определённую структуру. Подробную информацию можно найти в
файле [Структура файлов описания страниц и элементов.md](instructions/Структура файлов описания страниц и элементов.md)
