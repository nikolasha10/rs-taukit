# Tau-Tests
Фреймворк автотестирования, входящий в набор инструментов автоматизации тестирования TAU-KIT (Test Automation Utilities KIT)

<h3>Перед началом работы</h3>
1. Склонировать проект фреймворка с репозитория GitLab: 
    <p> git clone <a>http://git.dos.softlab.ru/kudryashov/rs-taukit.git</a> </p>
2. Открыть в терминале папку src
3. Склонировать проект автотестов ЕФР с репозитория GitLab:
    <p>git clone <a>http://git.dos.softlab.ru/kudryashov/efr-at.git</a></p>
4. Пометить папку <a>src/efr-at/java</a> ,как <i>Test Sources Root</i> (правой кнопкой мыши - Mark Directory as)
5. Пометить папку <a>src/efr-at/resources</a>, как <i>Test Resources Root</i>
6. Открыть File -> Setting -> Plugins и проверить, установлены ли плагины:
   - Cucumber for Java
   - Gherkin
   - Lombok
7. Открыть любой сценарий, например <a>src/efr-at/resources/scenarios/000. Подготовка тестовых условий/001. Установка настроек.feature</a>
8. Убедиться в том, что
   - файлы *.feature ассоциированы с Cucumber (ассоциировать можно в настройках File -> Settings -> Editor -> File Types)
   - ключевые слова (Функционал, Сценарий) подсвечиваются;
   - шаги не подсвечиваются (если выделены желтым, какая-то проблема с плагином cucumber for java);
   - русские слова не подчеркнуты (можно отключить проверку в настройках File -> Settings -> Editor -> Inspections -> Internationalization -> Non-ASCII characters);
9. Открыть конфигурацию запуска
10. Добавить новую конфигурацию TestNG
11. Настроить параметры:
    - Test kind: Method
    - Class: EFRTestRunner
    - Method: runByTag()
12. Открыть файл с настройками запуска тестов <a>src/efr-at/resources/configs/taukit.properties</a>
13. Если русские буквы отображаются некорректно, например, в виде кодов ascii: 
    - открыть настройки Settings -> File Encodings
    - указать кодировку для Default encoding for properties files: UTF-8
    - снять чекбокс Transparent native-to-ascii conversion и нажать Apply
    - снова установить чекбокс Transparent native-to-ascii conversion и нажать Apply
14. Сделать его копию с названием runtime.properties (этот файл добавлен в .gitignor, так что можно его править, не боясь случайно закоммитить неправильные настройки)
15. Распаковать архив browserExtensions/chromium.7z в ту же папку, где он находится (можно в другую, но тогда изменить значение настройки browser.extensions)
16. Изменить настройки в соответствии с текущими условиями (например, указать стенд) и запустить тест @000.001.001 (будут загружены браузеры, которые использует фреймворк. Тест в итоге может упасть по таймауту или с другой ошибкой, при первом запуске это не имеет значения)

<h3>Автотесты</h3>
Сценарии автотестов расположены в папке resources/scenarios в виде файлов с расширением feature.
Feature-файл имеет определённую структуру и содержит служебные слова, задающие значения переменным, необходимым для правильной работы фреймворка:
  - Функционал: содержит два значения - Название набора и Название функционала, взятых в квадратные скобки. Для правильной сортировки результатов в Allure-отчетах названию предшествует порядковый номер.
  - Сценарий: содержит название сценария. Должно быть уникальным в контексте указанного функционала. Также содержит порядковый номер в начале.
  - каждый шаг начинается с новой строки с символа * (правильнее было бы указывать аннотацию Gherkin, но в текущей реализации фреймворка в этом мало смысла)

Перед указанием функционала и сценария указываются с помощью символа @ задаются теги, позволяющие управлять составом запускаемых сценариев.
Теги, указанные перед словом Функционал относятся ко всем сценариям, описанным в этом feature-файле.
Теги, указанные перед словом Сценарий относятся только к данному сценарию.
Один и тот же тег может ссылаться на разные сценарии, в том числе и в разных файлах.

Теги можно перечислять в одной строке через пробел или в разных строках. 
Для запуска сценариев из Идеи необходимо указать теги через запятую в качестве значения опции scenario.tags в файле runtime.properties. 
 
Сценарий может быть описан как примитивными шагами, имеющими реализацию непосредственно в одном из Java-методов, так и с помощью шагов, вызывающих другой сценарий, описанный в том же виде.

Сценарии, вызываемые из основных сценариев называются фрагментами или подсценариями и представлены в виде feature-файлов в папке scenarioFragments.
Любой фрагмент также может быть вызван из другого фрагмента или даже из самого себя (при условии, что реализация шагов не допускает бесконечного зацикливания).

Фрагменты можно вызывать с параметрами, переданными в виде таблицы данных (как, например, в 001. Действующий клиент. Короткая анкета. Выдача.)
Также, в вызываемых фрагментах по умолчанию доступны тестовые параметры, значения которых были заданы в основном сценарии.

Любой шаг сценария связан с java-методом, определяющим его реализацию. Перейти к этому методу можно по CTRL + click.
Плагин Cucumber for Java находит метод, соответствующий конкретному шагу с помощью регулярного выражения, заданного в аннотации Gherkin (@И, @Когда, @Тогда, @То и других).
В текущей реализации фреймворка было решено не использовать другие аннотации, кроме @И, для упрощения работы со сценариями.

Важно учесть, что каждый шаг должен соответствовать только одному методу с аннотацией @И, независимо от класса.
Такой метод является лишь "описанием" шага и не должен содержать реализации действий с объектами тестирования и сложной логики. 
Обычно метод, описывающий шаг, создаёт экземпляр класса, содержащего поля и методы тестируемого объекта и вызывает соответствующий метод этого класса.   

В начале сценария в большинстве случаев бывает удобно выполнить шаг, определяющий значения переменных, которые в дальнейших шагах будут использоваться для заполнения полей, проверки их значений и т.п.
Для удобного хранения и представления тестовых данных используются файлы в формате yaml.
Чтобы шаг <u><i>* определить значения тестовых параметров</i></u> смог найти нужный файл, он должен располагаться в той же папке, что и feature-файл и иметь такое же название.
Кроме того, yaml-файл должен содержать элемент списка с полем Сценарий, имеющим в качестве значения название сценария, тестовые данные которого он описывает.

Для взаимодействия с элементами веб-страниц, фреймворк должен располагать информацией об этих элементах.
Для описания страниц используются yaml-файлы, которые расположены в папке resources/pages.
Файл страницы должен содержать определённую структуру. Подробную информацию можно найти в файле [Структура файлов описания страниц и элементов.md](src/efr-at/resources/pages/Структура файлов описания страниц и элементов.md)
